qonto-project-burn

Ce que le projet X a vraiment coûté — le burn réel par projet, écrit là où l'équipe vit.

📊 Burn réel vs budget déclaré🔒 Qonto en lecture seule 🧩 Linear/Jira optionnel, détecté🌍 Universel (tous pays Qonto)

🎯 Le pitch

Les équipes pilotent dans Linear ou Jira ; la dépense, elle, vit dans Qonto. Résultat : personne ne sait ce que le projet X a réellement coûté — SaaS dédiés, freelances, pubs, matériel. Le skill referme ce fossé :

1

Mapping labels ↔ projets

Table de config simple proposée depuis les labels Qonto, corrigeable ligne par ligne, mémorisée dans la conversation ou le projet Claude.

2

Burn réel vs budget

Jusqu'à 36 mois scannés (renouvellements annuels inclus), avoirs déduits, orphelines listées à part — jamais attribuées en douce.

3

Date de dépassement projetée

Rythme mensuel courant → « au rythme actuel, Alpha dépasse le 12/08 », tags de confiance 🟢🟡, seuils ⚠️ 80 % · 🔴 100 %.

4

Statut là où l'équipe vit

Avec accord : commentaire « X € / Y € — Z % » sur le projet Linear/Jira + issue d'alerte si seuil franchi, transactions Qonto à l'appui.

⚙️ Fonctionnement global

Ce qui rend le skill robuste sur données sales

  • Aucun label ? Mapping proposé depuis les fournisseurs récurrents, tout en 🟡, avec le mode d'emploi pour labelliser dans l'app Qonto
  • Transactions orphelines : listées avec compte et total, deux options de rangement — jamais attribuées en douce à un projet. Le MCP n'a pas d'outil pour attacher un label : liste prête à traiter dans l'app, ou classement optionnel via modify_transaction_cash_flow_category (écriture légère, réversible, confirmée)
  • Transaction multi-labels : comptée une fois, premier label du mapping — annoncé dans le rapport
  • Cadences annuelles : scan sur 24-36 mois quand l'historique le permet — les licences SaaS annuelles ne passent pas entre les mailles
  • Avoirs déduits · délais carte (emitted_at vs settled_at) · multi-comptes gérés · pagination ≤ 50 partout
  • Pas de MCP Linear/Jira ? Le skill le dit et livre le rapport complet + dashboard — le cœur marche en Qonto pur

🏗 Schéma fonctionnel

🔒

Côté Qonto, tout est en lecture — aucun virement, aucun paiement, rien qui touche à l'argent. Le trait pointillé (écriture) part vers Linear/Jira, pas vers la banque : un commentaire ou une issue, toujours prévisualisés en texte intégral et publiés uniquement après l'accord explicite dans la conversation.

🎬 Vidéo de démo

La démo ≤ 3 min jointe à la PR suit le storyboard : problème → mapping → burn & dates de dépassement → l'issue « ⚠️ Budget Alpha 87 % » découverte dans Linear, transactions Qonto à l'appui → dashboard final. Le script détaillé de tournage est conservé en interne (hors dépôt).

🛡 Garde-fous

  • Jamais d'écriture dans Linear/Jira sans prévisualisation du texte exact et confirmation explicite dans la conversation en cours ; jamais présentée comme faite si l'appel a échoué
  • L'attribution label → projet est toujours montrée et corrigeable — aucune réattribution silencieuse
  • Budgets = déclarés par l'utilisateur ; dépenses = données Qonto ; le skill n'invente ni l'un ni l'autre
  • list_cash_flow_categories → 403 sur le connecteur claude.ai : attendu, repli sur les labels
  • IBAN masqués (4 derniers chiffres) · pagination ≤ 50 · dégradation honnête (pas de labels, historique court, pas de MCP tracker)

Pour la vue entreprise (runway, cockpit tous coûts) : le skill qonto-ceo-cockpit. Ici, c'est la granularité projet.
