# Qonto Project P&L

Studios, agencies and indie hackers document their projects in Notion, but per-project profitability stays a mystery. This skill computes the truth from the bank — real cashed revenue AND attributed costs, hence margin — and writes it where the documentation lives. Qonto side: **read-only, zero writes**. The only write is in Notion, in a dedicated generated database, always previewed and confirmed.

## Prerequisites
1. `get_organization` **first** → accounts, currency, `bank_account_id` (required by `list_transactions`). Nothing hardcoded; adapts to any organization.
2. `list_labels` → the label tree is the candidate project list. No labels at all? Degrade honestly: propose a mapping from recurring counterparties instead, everything tagged 🟡, and explain how to label transactions in the Qonto app.
3. **Country-agnostic**: labels + invoices + transactions, no tax rules — works identically for every Qonto country (FR, DE, ES, IT, AT, NL, BE, PT).
4. **Notion MCP is optional, detected dynamically**: with the official Notion connector, the skill maintains the Finance database. Without it, say so plainly and run the degraded mode — full per-project P&L as tables in the conversation + an HTML dashboard. The core works on Qonto alone.

## Workflow

### 1. Read the account
`get_organization`, then `list_labels` (paginate `per_page: "50"`). Present the labels found. ⚠️ Do NOT call `list_cash_flow_categories` for the mapping — it returns **403 missing oauth scope** on the claude.ai connector; labels are the project dimension here.

### 2. Build the label ↔ project mapping — shown, confirmed, remembered
Propose a table: **Qonto label → project name → Notion page (if the connector is present) → client(s)**. Show it, let the user correct any line, then output a compact paste-ready block so it can be **remembered in the conversation or the Claude project instructions**. On re-runs, recall the stored mapping and only confirm what changed. Nothing is ever written to Qonto.

### 3. Revenue — cashed only
`list_client_invoices` (paginate ≤ 50) with statuses. **Revenue = paid invoices matched to incoming transactions** (amount + date window + normalized counterparty); show the match table and let the user confirm ambiguous pairs — never silent matching. Attribute each invoice to its project via the mapping (client → project, or the label carried by the incoming transaction). An issued-but-unpaid invoice is **never revenue**; past its `due_date` it becomes an ⚠️ overdue alert on its project. No invoices in Qonto? Fall back to labelled credits, tagged 🟡, and say the overdue detection is unavailable.

### 4. Costs and the P&L
`list_transactions` per account, `per_page: "50"`, side `debit`, scanning **24–36 months** when history allows so *annual* renewals (yearly SaaS licences, domain fees) show up, not just monthly ones. Then per project:
- Group debits by mapped label; deduct refunds/credits on the same counterparty; use `emitted_at` for card spend (1–2 days ahead of `settled_at`). A transaction carrying several labels counts **once**, under the mapping's first matching label — say so.
- **Orphans**: unlabelled debits matching a project's recurring suppliers are listed separately, never silently attributed (the MCP has no tool to attach a label — give a paste-ready list to label in the Qonto app).
- Compute: **cashed revenue · attributed costs · margin (€ and %) · monthly burn** (average of the last 3 full months, recent months weighted).
- **Alerts**: ⚠️ overdue invoice (from step 3) · ⚠️ unusual cost (a month > 1.5× the project's trailing 6-month average, the offending transactions listed) · 🔴 negative margin. Confidence tags: 🟢 fully labelled & matched / 🟡 orphans pending, fallback data or history < 3 months.

### 5. Write the Finance database in Notion — only with explicit consent
If the Notion connector is detected and the user confirms after a preview of the exact content:
- **First run**: create a dedicated database named **"Finance — P&L (generated by qonto-project-pnl)"**, under a page the user designates. One entry per project: cashed revenue · attributed costs · margin (€ / %) · monthly burn · alerts · period covered · last updated.
- **Every next run**: update each entry **in place, matched by project name** — idempotent, no duplicates, and pages the user renamed or moved are found again by their project property. New project in the mapping → new entry; vanished label → entry flagged, never deleted.
- The skill **never touches any other Notion content** — no existing page or database is edited, ever. If a Notion call fails, say so plainly; never present the write as done.

### 6. Report — output formats
**Always** reply in the conversation with markdown tables:
1. **Per-project P&L table**: project · cashed revenue · costs · margin € · margin % · monthly burn · alerts · confidence.
2. **Alert list** (overdue invoices with amounts and days late; unusual costs with the transactions behind them).
3. **Orphan list** (count + total) with the clean-up option.

**Additionally, when the host renders files** (claude.ai artifacts, Claude Desktop, Claude Code): an **HTML dashboard** — one row per project, revenue vs costs bars, margin badge, burn sparkline, alert markers. If the host cannot render files, say nothing about it: the tables are the deliverable.

**Scope boundaries**: for cost-vs-declared-budget tracking with alerts posted to **Linear/Jira** (product teams), see `qonto-project-burn` — this skill is the **full P&L (revenue AND costs, margin) in the documentation tool**. For the company-wide view (runway, all-costs cockpit), see `qonto-ceo-cockpit`.

## Guardrails
- **Zero Qonto writes.** The only write is the dedicated, clearly marked Notion database — created and updated after a preview and an explicit "yes" in the current conversation; existing Notion content is never overwritten.
- **Idempotent by design**: re-running updates entries in place; it never duplicates and never deletes.
- The label → project mapping and the invoice ↔ transaction matching are **always shown and correctable** — never a silent attribution.
- Revenue is matched cash only; anything estimated or fallback-based carries a 🟡 tag. The skill never invents an amount.
- `list_cash_flow_categories` / `get_subscription` → 403 on the claude.ai connector: expected, fall back to labels.
- Mask IBANs (last 4 digits). Paginate everything (`per_page` ≤ 50). Degrade honestly on missing labels, missing invoices, short history, or absent Notion MCP.
