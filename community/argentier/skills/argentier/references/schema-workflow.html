Schéma workflow · produit (M0 + M1)
₳ Argentier
Comment l'agent transforme un compte Qonto en un plan d'action chiffré — ton vrai run-rate, pas ton relevé — puis prépare les livrables que tu envoies.
Qonto lecture seule
Stack : Next.js · Anthropic
Endpoint : /api/analyze
Modèle : claude-sonnet-5

Les principes du workflow

Lecture seule Qonto
Uniquement des GET. Aucun paiement, aucune résiliation automatique.
Le LLM classe, le moteur calcule
Claude ne pose que des étiquettes ; tout euro vient de engine.ts.
Zéro action bancaire — tu envoies
Argentier prépare les livrables ; l'envoi reste entre tes mains.

Les deux cerveaux (la règle d'or)

🧭 Claude catégorise
Étiquette chaque marchand : nature, pôle, action, risque, ratio d'économie. Rédige aussi les lettres.
Renvoie des labels et un ratio — jamais un montant.
⚙️ engine.ts calcule
Déterministe : run-rate, natures, pôles, score, runway, économies (mensuel × ratio), anomalies.
Tout euro affiché vient d'ici. Reproductible, testable.
Qonto (lecture seule) & engine.ts (€) Claude (étiquettes & lettres) Front (restitution) Toi (gate & envoi)
Rien n'est envoyé ni modifié sur le compte. Sans clés Qonto/Anthropic, le pipeline sert des données de démo (mock) pour rester démontrable ; avec les clés, il analyse le vrai compte. Le contrat AnalyzeResult (lib/types.ts) fait foi entre le back et le front.
