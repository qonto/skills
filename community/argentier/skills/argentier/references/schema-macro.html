ARGENTIER. Agent DAF
Comment l'agent lit un compte Qonto en lecture seule, benchmarke sur le web avec ton accord, et prépare des livrables — sans jamais agir à ta place.
Qonto lecture seule
Exécution : Claude Code
Compte : EI · perso + pro mêlés
Garde-fou : .claude/settings.json

La constitution — 4 règles non négociables

Règle 1
Read-only Qonto
Écriture dure-bloquée (deny > allow). Aucun mouvement d'argent.
Règle 2
engine.py calcule
Tout montant € vient du moteur. Le LLM ne fait aucune arithmétique.
Règle 3
Zéro PII vers le web
Vers le benchmark : nom du marchand + catégorie. Rien d'autre.
Règle 4
Prix = source + date
Sinon rejet, 1 retry, puis « non vérifié ». Jamais inventé.

La boucle de travail

Entrées
🔒 Qonto MCP
90 jours de transactions, cartes, virements. Ce que tu vois déjà dans Qonto.
Lecture seule
🌐 Web
Linkup / Bright Data — grilles tarifaires publiques du marché.
Nom + catégorie only
🗂️ Ton profil
data/profile.json — critères, fournisseurs intouchables, refus passés.
Commande /audit
OBSERVE → ANALYSE → BENCHMARK → RECOMMANDE → GATE → LEDGER
1
OBSERVEQonto
Lit 90 j de flux, les archive en local (data/flows-*.json, gitignorés).
2
ANALYSEengine.py
Récurrence, doublons, frais FX, tri PRO / PERSO / à-clarifier.
Récurrent = vu ≥ 2× / 90 j à montant similaire. Annualisation = mensuel × 12. Un one-off n'est jamais annualisé.
3
BENCHMARKWeb · sur accord
Compare les prix des plus gros postes. Déclenché seulement avec ton feu vert.
N'envoie que le nom du marchand + la catégorie. Aucune donnée du compte.
4
RECOMMANDEClaude
Une carte par levier : économie €/an (du moteur) + prix sourcé & daté.
Passe de vérification : chaque prix sans source datée est rejeté.
5
GATE HUMAINToi
Le livrable (mail, lettre) atterrit dans drafts/. Rien n'est envoyé.
« PRÊT — À ENVOYER PAR TOI »
6
LEDGERdecisions.json
Trace la décision : économie prouvée / en attente.
/verify À J+30, l'agent relit Qonto et prouve l'économie réelle — ou la reclasse en attente. La boucle se referme.
Sorties
✉️ drafts/
Mails & lettres prêts. Tu relis, tu approuves, tu envoies.
Jamais envoyé par l'agent
📒 decisions.json
Le ledger : décisions + économies prouvées et en attente.
📊 Dashboard
Rendu HTML de l'audit — postes, doublons, frais FX, variables.

Les deux cerveaux

⚙️ Le moteur engine.py
Déterministe. Détecte récurrences, doublons, frais de change ; classe PRO/PERSO/à-clarifier ; calcule chaque euro.
Règle 2 — c'est lui qui chiffre, jamais le LLM.
🧭 L'orchestrateur Claude
Lit Qonto, déclenche les benchmarks sur ton accord, rédige les cartes et les brouillons, tient le ledger.
Reprend les chiffres du moteur — n'en invente aucun.
