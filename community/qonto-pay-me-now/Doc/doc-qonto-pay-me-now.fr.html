qonto-pay-me-now

Du devis à l'argent, sans friction — le devis accepté devient facture, lien de paiement et encaissement.

✅ Payment links vérifiés via MCP💳 Paiement carte & virement 🔗 Lien court + QR trackable📄 PR-ready

🎯 Le pitch

Le trou noir du freelance : le devis est accepté… et puis rien. La facture attend, le paiement attend encore plus — chaque jour entre le « oui » et l'argent, c'est de la trésorerie gagnée mais intouchable. Le skill enchaîne tout le cycle dans une seule conversation :

1

Devis accepté détecté

Devis croisés avec les factures existantes — seuls les acceptés jamais facturés remontent, avec client, montant et date.

2

Facture depuis le devis

Brouillon d'abord, document RÉEL : relecture ligne par ligne, envoi seulement après ta confirmation explicite.

3

Payment link + QR

Le client paie par carte ou virement en un clic. Lien court trackable Short.io + QR code pour les factures imprimées.

4

Suivi & relance douce

Cliqué mais impayé après 48 h → relance douce proposée, rédigée — jamais envoyée toute seule.

Le cycle de paiement passe de « quand il y pense » à « il clique, il paie ».

⚙️ Fonctionnement global

Ce qui rend le skill robuste sur données sales

  • Le différenciateur : la doc MCP officielle liste les payment links comme non supportés — ils fonctionnent (vérifié en production le 03/07). Le skill appelle create_payment_link directement, sans se fier à la doc
  • Pas de devis accepté ? Le skill le dit et propose de partir d'une facture impayée existante — la suite du cycle est identique
  • Payment links non activés ? Activation unique expliquée (app Qonto), le cycle continue avec la facture seule
  • Short.io ou Gmail absents → lien Qonto brut + texte prêt à copier, annoncé clairement — aucun tracking simulé
  • Client payé par virement classique hors lien → rapprochement dans list_transactions (montant ± 0,01, contrepartie, référence) et mark_client_invoice_as_paid proposé avec preuve
  • TVA sur les encaissements (vat_payment_condition: "on_receipts") : accélérer le paiement accélère aussi le cycle de TVA — le skill le signale
  • Pagination ≤ 50 partout · numérotation laissée aux réglages de l'organisation · montants toujours repris du devis, jamais inventés

🏗 Schéma fonctionnel

🔒

Ce skill ne peut pas déplacer ton argent : un payment link est un moyen de recevoir un paiement de ton client — rien à voir avec un virement sortant (impossible via MCP de toute façon : toute demande de virement exige ta SCA dans l'app Qonto). Les trois seules écritures : une facture (brouillon d'abord, envoi après ton OK explicite), un lien de paiement désactivable à tout moment dans l'app, et le marquage « payée » — toujours proposé, jamais automatique.

🛡 Garde-fous

  • Factures via MCP = RÉELLES : brouillon d'abord, envoi seulement après confirmation explicite ; répétitions sur un client fictif + delete_client_invoice ensuite
  • Aucun paiement sortant : le payment link reçoit, il ne débite jamais — zéro rapport avec les virements sortants (SCA obligatoire dans l'app, hors MCP)
  • Rien n'est envoyé (facture, mail, relance) sans confirmation dans la conversation en cours ; jamais présenté comme envoyé/payé si en attente
  • Montants repris du devis ou de la facture, jamais inventés · IBAN masqués · pagination ≤ 50
  • Dégradation honnête : pas de devis, payment links non activés, Short.io absent, pays ≠ FR → le skill dit ce qui marche et continue avec ça
